<section class="attention-article"><p>Open the <a href="https://arxiv.org/pdf/2609.19969">DeepSeek-V4.1-Flash report</a> and the attention architecture comes with a small vocabulary of its own: CSA2, sparse indexing, cross-layer reuse. Open the <a href="https://arxiv.org/pdf/2607.24653">Kimi K3 report</a> and the names change: KDA, Gated MLA, hybrid attention. Several of these choices appear in the same model.</p>
<p>Why do we need so many kinds of attention? Which ones solve the same problem? Which can work together? And when a new architecture arrives, how do we tell what it actually changes?</p>
<p>Start with the job itself. <strong>Attention lets a model use the current position’s needs to retrieve and combine information from its context.</strong> A word need not rely only on its neighbors: information much farther away can influence its representation.</p>
<p>But a read needs something to read from. A model must also decide what to retain, how to represent it, and what happens when new information arrives. Seen together, these decisions define a <strong>context memory system</strong>. That is the thread we will follow: from reading context, to making that read affordable, to managing what the model carries forward.</p>
<figure id="n02-fork"><img alt="Keep entries, or carry a state?" decoding="async" loading="lazy" src="figures/en/attention-evolution-n02-fork.svg"/></figure><p class="figure-caption"><em>Figure 0.1. Two memory interfaces recur throughout the story: retained entries and recurrent state.</em></p><details><summary>Technical note: Keep entries, or carry a state?</summary><div class="detail-body"><p>An entry cache preserves an addressable history. A recurrent core merges contributions into a state of fixed feature dimensions. Neither diagram area nor tile count represents a measured capacity ratio. In the equations below, state matrices use key features as rows and value components as columns; fixed state size always assumes fixed feature widths and head counts.</p><div class="equation">Entry-cache size ∝ number of entries × elements per entry × independent cache layers

<p>The split in this picture will recur throughout the article. One path keeps historical entries that a later query can revisit. The other folds history into a state whose shape stays fixed. Both offer useful capabilities; both impose limits. A hybrid can use both.</p>

<h2 id="chapter-1">1. Why Attention Was Needed</h2>
<p>Before neural attention, machine translation already had ways to connect words across languages. Statistical translation used alignment models and phrase tables. Early neural sequence-to-sequence models took a different approach: an encoder read the source sentence, and a decoder generated the translation from a fixed-length representation. The recurrent neural network, or RNN, carried information forward through successive hidden states.</p>
<p>The bottleneck was easy to state: <strong>one representation had to carry everything the decoder would need from the source sentence.</strong> In the basic encoder–decoder arrangement, the decoder could not return to an individual source position whenever it needed more detail.</p>
<figure id="n01-history"><img alt="Translate by looking back at the source" decoding="async" loading="lazy" src="figures/en/attention-evolution-n01-history.svg"/></figure><p class="figure-caption"><em>Figure 1.1. A dynamic context vector gives each translation step its own read of the source.</em></p><details><summary>Technical note: Translate by looking back at the source</summary><div class="detail-body"><p>Statistical alignment preceded neural attention. The specific bottleneck illustrated is the basic fixed-vector neural encoder–decoder: its decoder receives a sentence representation rather than a fresh read of source positions. Bahdanau attention retains encoder annotations hⱼ and forms a new mixture for each decoder step. The weights shown are schematic.</p><div class="equation">cᵢ = Σⱼ αᵢⱼ hⱼ
αᵢⱼ = softmaxⱼ a(sᵢ₋₁, hⱼ)</div><p class="reference-note">Primary references: <a href="https://aclanthology.org/N03-1017.pdf">Statistical phrase-based translation</a>; <a href="https://arxiv.org/pdf/1409.3215">Sequence to Sequence Learning</a>; <a href="https://arxiv.org/pdf/1409.0473">Bahdanau attention</a>; <a href="https://aclanthology.org/D15-1166.pdf">Luong attention</a>.</p></div></details>
<p><a href="https://arxiv.org/pdf/1409.0473">Bahdanau attention</a> opened that return path. Retain the encoder’s position-wise representations; at each decoding step, score them against the decoder state and read a weighted combination. The context vector changes as the translation progresses. <a href="https://aclanthology.org/D15-1166.pdf">Luong attention</a> developed related alignment-based reads with different scoring and alignment choices.</p>
<p>The Transformer took the idea further. <strong>Self-attention connects positions within a sequence directly, replacing recurrence as the main sequence-mixing operation.</strong> For a known input sequence, the positions in a layer can be processed in parallel, subject to the attention mask. This offers both flexible contextual access and a computation that maps well to matrix operations.</p>
<figure id="n01-transformer"><img alt="Transformer connects positions directly" decoding="async" loading="lazy" src="figures/en/attention-evolution-n01-transformer.svg"/></figure><p class="figure-caption"><em>Figure 1.2. Self-attention provides a direct path between visible positions within a layer.</em></p><details><summary>Technical note: Transformer connects positions directly</summary><div class="detail-body"><p>In a recurrent layer, information is propagated along a sequence of state transitions. In self-attention, each query can read visible inputs to that layer directly. Known sequence positions can be processed together during training or prefill; autoregressive token generation is still sequential. The illustration uses causal visibility, including the current position.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>.</p></div></details>
<p>That combination helps explain attention’s central role in modern language models. It does not mean a model generates every future token simultaneously: autoregressive generation still feeds each newly generated token into the next step. Nor does attention replace the entire network. Feed-forward layers, normalization, residual connections, and training remain essential.</p>
<details class="extra"><summary>Inside a Transformer block: self-attention, cross-attention, and residual paths</summary><div class="extra-body">
<figure id="c2-vf-05-block"><img alt="Attention is one branch of a block" decoding="async" loading="lazy" src="figures/en/attention-evolution-c2-vf-05-block.svg"/></figure><p class="figure-caption"><em>Figure 1.3. Attention mixes positions inside a larger block; it is not the entire model.</em></p><details><summary>Technical note: Attention is one branch of a block</summary><div class="detail-body"><p>The diagram uses a pre-normalization residual layout. <p>Attention exchanges information between positions; the feed-forward network transforms each position’s features. Residual paths preserve a route around each branch. The illustration uses a modern pre-normalization block, rather than claiming that every Transformer uses this exact placement.</p>
<figure id="c2-vf-06-sources"><img alt="Self or cross? Check the sources" decoding="async" loading="lazy" src="figures/en/attention-evolution-c2-vf-06-sources.svg"/></figure><p class="figure-caption"><em>Figure 1.4. Self-attention and cross-attention are distinguished by where Q and KV come from.</em></p>
<p>The distinction between self-attention and cross-attention concerns the source of the vectors. In self-attention, queries, keys, and values come from the same sequence. In translation cross-attention, decoder queries read encoder keys and values. Causal masking is another decision: it determines which positions are visible.</p>
</div></details>
<p>Attention solved a read-access problem. Its next problem was the cost of keeping that access as context grew.</p>
<h2 id="chapter-2">2. Standard Attention: Flexible Reads, Growing Costs</h2>
<p>A position’s representation is projected into three vectors: a <strong>query</strong> Q, which specifies what to look for; a <strong>key</strong> K, which participates in matching; and a <strong>value</strong> V, which supplies the content to combine. These are learned vectors, not literal database fields.</p>
<p>We will reuse a small example: an earlier message names Shanghai as a destination, a later message changes it to Hangzhou, and the current message asks “Where?” The five text chunks in the diagrams make positions easy to track; they are not an actual tokenizer output. The weights are illustrations, not measurements of whether a trained model answers correctly.</p>
<figure id="n02-qkv"><img alt="Attention: match, then mix" decoding="async" loading="lazy" src="figures/en/attention-evolution-n02-qkv.svg"/></figure><p class="figure-caption"><em>Figure 2.1. A query matches visible keys, then combines the corresponding values.</em></p><details><summary>Technical note: Attention: match, then mix</summary><div class="detail-body"><p>For a full sequence, collect queries, keys, and values into matrices. Softmax operates along the key/history axis, independently for each query. The causal mask contributes zero at visible pairs and negative infinity at forbidden pairs. The result is a vector mixture whose width is the value width, not a selected token or a concatenation of all values.</p><div class="equation">Q = XW_Q; K = XW_K; V = XW_V
A = softmax_row(QKᵀ / √dₖ + M)
O = AV</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>.</p></div></details>
<p>The query scores every visible key. Softmax converts those scores into nonnegative weights summing to one, and the output is a weighted sum of value vectors. <strong>Attention mixes information; it does not ordinarily return the index of one winning word.</strong></p>
<p>Multi-head attention, or <strong>MHA</strong>, repeats this operation in several learned representation spaces. The heads’ output vectors are concatenated and then mixed by an output projection. A head may learn a useful pattern of interaction, but the architecture does not assign it a human-readable job in advance.</p>
<figure id="c2-vf-04-heads"><img alt="Read per head, then concatenate" decoding="async" loading="lazy" src="figures/en/attention-evolution-c2-vf-04-heads.svg"/></figure><p class="figure-caption"><em>Figure 2.2. Each head returns a vector; concatenate those vectors before the output projection.</em></p><details><summary>Technical note: Read per head, then concatenate</summary><div class="detail-body"><p>Different heads use learned projections and form their own attention weights. Their value-weighted outputs are concatenated along the feature axis. The output projection mixes those features back into model width. The illustrated head count and vector components are teaching choices, not a particular model configuration.</p><div class="equation">oₜ⁽ʰ⁾ = Σⱼ aₜⱼ⁽ʰ⁾ vⱼ⁽ʰ⁾
O = Concat(O⁽¹⁾, …, O⁽ᴴ⁾) W_O</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>.</p></div></details>
<p>Long context brings several costs that are easy to confuse. Processing an entire sequence involves a grid of query–key pairs. Decoding one additional position involves one new query, but it still reads the visible history. Intermediate matrices, retained KV, and transfers through the memory hierarchy are separate costs.</p>
<figure id="c2-vf-09-costs"><img alt="Four separate costs of long context" decoding="async" loading="lazy" src="figures/en/attention-evolution-c2-vf-09-costs.svg"/></figure><p class="figure-caption"><em>Figure 2.3. Pairwise work, intermediate storage, persistent KV, and data movement are different costs.</em></p><details><summary>Technical note: Four separate costs of long context</summary><div class="detail-body"><p>A full sequence has a query–key grid that grows quadratically in its length. One cached decode step adds a single query row but reads a history that grows with context. The full intermediate matrix need not be stored, even when all the pairwise scores still participate in the computation. Persistent KV is a separate object.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>; <a href="https://arxiv.org/pdf/2205.14135">FlashAttention, §3 / Algorithm 1</a>; <a href="https://arxiv.org/pdf/1911.02150v1">Fast Transformer Decoding</a>.</p></div></details>
<p>A <strong>KV cache</strong> saves each processed position’s keys and values so later steps can reuse them. It avoids reprojecting the old positions; it does not make their storage or later reads free. This distinction explains why “faster attention” can mean several very different changes.</p>

<p>The current token supplies a new Q, K, and V. Older K and V remain valid because causal processing did not depend on future tokens. Each attention layer maintains its own cache under the ordinary arrangement.</p>
<pre><code class="language-python">import math
import torch

def causal_attention(q, k, v):
    # A complete sequence, no padding or cached prefix.
    n = q.shape[-2]
    score = q @ k.transpose(-2, -1)
    score = score / math.sqrt(q.shape[-1])
    future = torch.ones(n, n, device=q.device,
                        dtype=torch.bool).triu(1)
    score = score.masked_fill(future, -float('inf'))
    weight = score.float().softmax(-1).to(v.dtype)
    return weight @ v</code></pre>
<p>This is a teaching implementation. A cached decode call can have different query and key lengths, and masking must account for the prefix length. Production kernels also handle padding, layouts, precision, and batching.</p>
</div></details>
<p>We can now separate two questions: can we make each stored entry smaller, and can we avoid reading every entry?</p>
<h2 id="chapter-3">3. MQA and GQA: Sharing the KV Cache</h2>
<p>MHA gives every query head its own key and value heads. That provides flexibility, but the cache retains many parallel descriptions of the same historical positions.</p>
<p><strong>Multi-query attention (MQA)</strong> shares one KV head across all query heads. <strong>Grouped-query attention (GQA)</strong> takes an intermediate position: query heads are divided into groups, with one KV head per group. The number of query heads need not change.</p>
<figure id="c3-vf-01-head-map"><img alt="Keep query heads; share KV heads" decoding="async" loading="lazy" src="figures/en/attention-evolution-c3-vf-01-head-map.svg"/></figure><p class="figure-caption"><em>Figure 3.1. MQA and GQA share the KV heads without removing query heads.</em></p><details><summary>Technical note: Keep query heads; share KV heads</summary><div class="detail-body"><p>Let g(h) identify the KV group for query head h. Each head h has its own query and normalization over history, but reads the keys and values of group g(h). One group gives MQA; one KV group per query head gives MHA. Shared KV is not shared attention weights.</p><div class="equation">aₜⱼ,ₕ = softmaxⱼ(qₜ,ₕᵀ kⱼ,g(h) / √dₖ + Mₜⱼ)
oₜ,ₕ = Σⱼ aₜⱼ,ₕ vⱼ,g(h)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2305.13245">GQA, §2.2</a>; <a href="https://arxiv.org/pdf/1911.02150v1">Fast Transformer Decoding</a>.</p></div></details>
<p>The saving is on the <strong>head axis</strong> of the cache. Sharing does not force the query heads to produce identical attention weights: different queries can match the same keys differently. GQA offers a way to trade KV capacity and bandwidth against representational freedom; the quality outcome depends on the model and its training.</p>
<details class="extra"><summary>Shared keys, different reads; smaller entries, growing history</summary><div class="extra-body">
<figure id="c3-vf-02-shared-weights"><img alt="Shared KV need not mean shared output" decoding="async" loading="lazy" src="figures/en/attention-evolution-c3-vf-02-shared-weights.svg"/></figure><p class="figure-caption"><em>Figure 3.2. Two queries can retrieve different mixtures from the same KV group.</em></p><details><summary>Technical note: Shared KV need not mean shared output</summary><div class="detail-body"><p>The key and value content is shared, but the query vectors are not. Their dot products can therefore differ, producing different normalized weights and output vectors. The bars illustrate this distinction; they are not measurements on the destination example.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2305.13245">GQA, §2.2</a>; <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>.</p></div></details>
<figure id="c3-vf-03-cache-axes"><img alt="Fewer heads, but history still grows" decoding="async" loading="lazy" src="figures/en/attention-evolution-c3-vf-03-cache-axes.svg"/></figure><p class="figure-caption"><em>Figure 3.3. Head sharing shrinks each history row, while each new position still adds a row.</em></p><details><summary>Technical note: Fewer heads, but history still grows</summary><div class="detail-body"><p>These shapes count persistent elements before multiplying by element precision. They assume one full-history cache per layer, without cross-layer sharing. Batch size and the number of layers multiply the total, and padding or implementation layout can add further storage.</p><div class="equation">Q: [B, Hq, N, dₖ]

<p>For batch B, history N, and Hkv KV heads, a layer stores B·N·Hkv·(dₖ+dᵥ) elements. Reducing Hkv shrinks each history row. The N factor remains.</p>
<pre><code class="language-python"># Teaching expansion of grouped KV for a complete causal sequence.
# q: [B, Hq, N, dk]; k/v: [B, Hkv, N, dk/dv]
assert q.shape[1] % k.shape[1] == 0
repeat = q.shape[1] // k.shape[1]
k_expanded = k.repeat_interleave(repeat, dim=1)
v_expanded = v.repeat_interleave(repeat, dim=1)

<p>Explicit repetition makes the correspondence visible but loses the implementation advantage. An efficient GQA kernel reuses shared KV instead of creating all those copies.</p>
</div></details>
<p>MQA and GQA share heads. MLA asks whether the heads’ information can instead share a compact representation.</p>
<h2 id="chapter-4">4. MLA: Compressing Each Memory Entry</h2>
<p><strong>Multi-head latent attention (MLA)</strong>, introduced in DeepSeek-V2, jointly encodes a position’s multi-head key and value information in a lower-dimensional <em>latent</em> vector. Here “latent” simply means a learned compact representation.</p>
<figure id="c4-vf-01-latent-cache"><img alt="MLA compresses entries, not history" decoding="async" loading="lazy" src="figures/en/attention-evolution-c4-vf-01-latent-cache.svg"/></figure><p class="figure-caption"><em>Figure 4.1. A latent cache keeps one compressed representation per historical position.</em></p><details><summary>Technical note: MLA compresses entries, not history</summary><div class="detail-body"><p>DeepSeek-V2 jointly compresses a position’s content K/V into cⱼ. Its decoupled positional branch additionally retains kᴿⱼ. Low-rank feature compression reduces each entry’s width; it does not remove the history-length factor. Other MLA configurations can use different positional choices.</p><div class="equation">cⱼ = Wᴰᴷⱽ xⱼ
Content cache: [B, N, d_c]
Positional-key cache: [B, N, d_r]
Elements per layer: B·N·(d_c+d_r)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2405.04434">DeepSeek-V2, §2.1</a>; <a href="https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py">Author implementation</a>.</p></div></details>
<p>There is still a separate entry for each historical position. <strong>MLA compresses the feature representation of an entry; it does not turn the whole history into one fixed state.</strong> The latent can feed different per-head projections, so this is a different constraint from making all heads share identical K and V.</p>
<p>Compression is only half the design. If decoding immediately expanded every old latent into full multi-head K/V, much of the transfer advantage would be lost. MLA can absorb the key projection into the query path and move value expansion after weighted latent aggregation.</p>
<figure id="c4-vf-03-absorption"><img alt="Move projections to the query and output" decoding="async" loading="lazy" src="figures/en/attention-evolution-c4-vf-03-absorption.svg"/></figure><p class="figure-caption"><em>Figure 4.2. Linear projections can move to the query side and after weighted aggregation.</em></p><details><summary>Technical note: Move projections to the query and output</summary><div class="detail-body"><p>For one head’s content branch, move the key up-projection onto the query before reading cached latents. On the value side, sum weighted latents before up-projecting. This avoids first expanding every historical position’s full K/V. Efficient execution still depends on layouts and kernels; the identities alone are not a measured speedup.</p><div class="equation">qᶜᵀ(Uᴷcⱼ) = (Uᴷᵀqᶜ)ᵀcⱼ
Σⱼ aⱼ(Uⱽcⱼ) = Uⱽ(Σⱼ aⱼcⱼ)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2405.04434">DeepSeek-V2, §2.1</a>; <a href="https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py">Author implementation</a>.</p></div></details>
<p>That rearrangement relies on linear algebra. Position-dependent transformations complicate it. DeepSeek-V2 separates the content path from a rotary positional path, preserving the useful absorption while retaining positional matching.</p>
<details class="extra"><summary>Latent expansion, projection absorption, and the RoPE complication</summary><div class="extra-body">
<figure id="c4-vf-02-latent-expand"><img alt="One latent, different per-head K/V" decoding="async" loading="lazy" src="figures/en/attention-evolution-c4-vf-02-latent-expand.svg"/></figure><p class="figure-caption"><em>Figure 4.3. It does not require every expanded key or value head to be identical. The diagram shows only the content branch and two illustrative heads.</p><div class="equation">kᶜⱼ,ₕ = Uᴷₕ cⱼ; vⱼ,ₕ = Uⱽₕ cⱼ

It cannot generally be precomputed once as a fixed transform of the current query. This motivates the separate positional path in DeepSeek-V2 MLA.</p><div class="equation">Content score with rotations: qᵢᵀ Rᵢᵀ Rⱼ Uᴷ cⱼ
Query-side factor: Uᴷᵀ Rⱼᵀ Rᵢ qᵢ, which depends on j</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2405.04434">DeepSeek-V2, §2.1</a>; <a href="https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py">Author implementation</a>; <a href="https://arxiv.org/pdf/2104.09864">RoFormer, §3.2</a>.</p></div></details>
<p><strong>Rotary position embedding (RoPE)</strong> rotates query and key feature pairs according to their positions. If a historical key’s rotation sits between the query and its up-projection, that rotation changes with the historical position. One fixed query-side projection cannot generally absorb all of them.</p>
<figure id="c4-vf-05-decoupled-rope"><img alt="Separate content from position" decoding="async" loading="lazy" src="figures/en/attention-evolution-c4-vf-05-decoupled-rope.svg"/></figure><p class="figure-caption"><em>Figure 4.5. Combine a compressed content score with a separate positional score.</em></p><details><summary>Technical note: Separate content from position</summary><div class="detail-body"><p>The positional key is shared across heads in this DeepSeek-V2 layout. Content matching can still use the absorbed query transform. Add content and positional scores before scaling, masking, and softmax; the scaling dimension includes both contributing key subspaces.</p><div class="equation">s_content = (Uᴷₕᵀqᶜₜ,ₕ)ᵀcⱼ
s_position = qᴿₜ,ₕᵀkᴿⱼ
aₜⱼ,ₕ = softmaxⱼ((s_content+s_position)/√(dₖᶜ+d_r) + Mₜⱼ)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2405.04434">DeepSeek-V2, §2.1</a>; <a href="https://github.com/deepseek-ai/DeepSeek-V3/blob/main/inference/model.py">Author implementation</a>.</p></div></details>
<figure id="c2-vf-07-position"><img alt="Position changes the match" decoding="async" loading="lazy" src="figures/en/attention-evolution-c2-vf-07-position.svg"/></figure><p class="figure-caption"><em>Figure 4.6. Relative rotation changes a query–key match without changing the underlying content vectors.</em></p><details><summary>Technical note: Position changes the match</summary><div class="detail-body"><p>RoPE acts on two-dimensional feature pairs. Moving a key changes its relative angle to a fixed query. Shifting both positions together preserves their relative angle in this construction. The diagram is one subspace with illustrative angles, not a visualization of a complete model embedding.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2104.09864">RoFormer, §3.2</a>.</p></div></details>
<p>For DeepSeek-V2-style MLA, the cache therefore contains a content latent plus a positional key. This is a configuration-specific description: later models can make different positional choices. Kimi K3’s MLA uses No Position Encoding (NoPE), as we will see in Chapter 10.</p>
</div></details>
<p>Even a compact entry must still be read. The next group of designs reduces how much history participates in a read.</p>
<h2 id="chapter-5">5. Sparse Attention: Reading Less History</h2>
<p>A local window is the simplest restriction: read nearby positions and exclude the rest from this layer’s direct read. Global positions can add longer-range links. These patterns alter access, rather than merely changing how a cache entry is represented.</p>
<p><strong>Mixture of Block Attention (MoBA)</strong> makes the selection depend on the query. Summarize blocks, score the summaries, select blocks, and attend to the tokens inside them. The current block remains available under a causal mask.</p>
<figure id="c5-vf-02-moba"><img alt="MoBA: select blocks, then read tokens" decoding="async" loading="lazy" src="figures/en/attention-evolution-c5-vf-02-moba.svg"/></figure><p class="figure-caption"><em>Figure 5.1. MoBA routes a query to blocks before reading their individual tokens.</em></p><details><summary>Technical note: MoBA: select blocks, then read tokens</summary><div class="detail-body"><p>Mean keys provide coarse block summaries. Select completed past blocks by their query scores, while also reading the causally visible part of the current block. Future positions remain masked. The block choices shown illustrate routing, rather than measured relevance or a guaranteed speedup.</p><div class="equation">k̄_b = meanⱼ∈block_b(kⱼ)
s_b = qₜᵀk̄_b
Read set = selected past blocks ∪ visible current-block positions</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2502.13189">MoBA, §2</a>.</p></div></details>
<p>Selection is approximate routing: a block summary cannot retain every detail of every key. It also has its own cost. Fewer token-level pairs do not automatically translate into the same factor of wall-clock speedup.</p>
<p>Another choice is to compress groups of historical positions. DeepSeek-V4’s <strong>Compressed Sparse Attention (CSA)</strong> selects from a compressed pool and combines the selected entries with local KV. Its <strong>Heavily Compressed Attention (HCA)</strong> reads a more aggressively compressed visible pool together with local KV. Both can build one combined KV set for the core attention read.</p>
<figure id="n05-csa"><img alt="Build one KV set, then attend" decoding="async" loading="lazy" src="figures/en/attention-evolution-n05-csa.svg"/></figure><p class="figure-caption"><em>Figure 5.2. CSA/HCA form a combined local-and-historical KV set for one normalized read.</em></p><details><summary>Technical note: Build one KV set, then attend</summary><div class="detail-body"><p>DeepSeek-V4 CSA compresses overlapping groups and selects from its compressed pool. HCA uses heavier, non-overlapping compression and reads the visible compressed pool. The core sketch concatenates retained KV entries before attention. This differs from NSA’s weighted sum of independently computed branch outputs.</p><div class="equation">o = Attn(q, concat(K_local, K_history), concat(V_local, V_history))
NSA instead: o = g_cmp·o_cmp + g_sel·o_sel + g_win·o_win</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2606.19348">DeepSeek-V4, §2.3</a>; <a href="https://arxiv.org/pdf/2502.11089">Native Sparse Attention, §3</a>.</p></div></details>
<p>That combination matters: concatenating KV entries before one normalization is different from gating several independently normalized branch outputs. <strong>Native Sparse Attention (NSA)</strong> uses the latter pattern, combining compressed, selected, and local branch outputs with learned gates.</p>

<p>Sharing, compression, and sparse reads preserve some form of revisitable history. What if the model did not keep a separately addressable entry for every position?</p>
<h2 id="chapter-6">6. Linear Attention: Replacing History with a State</h2>
<p>A <strong>recurrent state</strong> is the information carried from one step to the next. Linear attention can accumulate key–value associations into a fixed-shape matrix and query that matrix later. Its storage no longer needs a new row for every historical position.</p>
<figure id="n06-return"><img alt="A fixed state avoids revisiting entries" decoding="async" loading="lazy" src="figures/en/attention-evolution-n06-return.svg"/></figure><p class="figure-caption"><em>Figure 6.1. A fixed state replaces per-position revisits with a learned associative read/write interface.</em></p><details><summary>Technical note: A fixed state avoids revisiting entries</summary><div class="detail-body"><p>This is a return to finite memory, not a return to the unchanged early Seq2Seq model. Modern recurrent forms specify how keys write associations and queries read them. Their core state size can stay independent of history length, but direct access to every individual historical representation is no longer available.</p><p class="reference-note">Primary references: <a href="https://aclanthology.org/N03-1017.pdf">Statistical phrase-based translation</a>; <a href="https://arxiv.org/pdf/1409.3215">Sequence to Sequence Learning</a>; <a href="https://arxiv.org/pdf/1409.0473">Bahdanau attention</a>; <a href="https://aclanthology.org/D15-1166.pdf">Luong attention</a>; <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>.</p></div></details>
<p>This revisits the old finite-memory constraint, but with a much more explicit read/write interface than the basic encoder–decoder bottleneck. A key determines how to write an association; a query determines how to read it. The state’s rows are learned key features, not token positions.</p>
<figure id="n06-state"><img alt="One state can answer different queries" decoding="async" loading="lazy" src="figures/en/attention-evolution-n06-state.svg"/></figure><p class="figure-caption"><em>Figure 6.2. Different query directions can retrieve different associations from the same matrix state.</em></p><details><summary>Technical note: One state can answer different queries</summary><div class="detail-body"><p>For the teaching example, two nonnegative key-feature directions are orthogonal and each has been written once. Their reads do not interfere, and both normalization denominators equal one. Learned feature directions in a real model need not be orthogonal or correspond to named semantic categories.</p><div class="equation">Sₜ = Sₜ₋₁ + φ(kₜ)vₜᵀ; zₜ = zₜ₋₁ + φ(kₜ)
oₜ = Sₜᵀφ(qₜ) / (zₜᵀφ(qₜ))</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>.</p></div></details>
<p>The benefit is clear: the recurrent core can update and read a state of constant shape at each decode step. The constraint is equally important: <strong>historical contributions now share a finite representation.</strong> They are no longer independent entries waiting to be revisited.</p>
<figure id="n06-interference"><img alt="Repeated keys mix their values" decoding="async" loading="lazy" src="figures/en/attention-evolution-n06-interference.svg"/></figure><p class="figure-caption"><em>Figure 6.3. Writing two values with the same key makes their contributions share a state direction.</em></p><details><summary>Technical note: Repeated keys mix their values</summary><div class="detail-body"><p>The normalized nonnegative-kernel example reads an average of the two values. This isolates interference without claiming a trained model must fail a particular language task. Close rather than identical key directions can also interact. Fixed shape is a storage property, not unlimited information capacity.</p><div class="equation">φ(k₁)=φ(k₂)=φ(q)=(1,0)ᵀ
v₁=(1,0)ᵀ; v₂=(0,1)ᵀ
S=[[1,1],[0,0]]; z=(2,0)ᵀ
o = Sᵀφ(q)/(zᵀφ(q)) = (½,½)ᵀ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>.</p></div></details>
<p>In the nonnegative-kernel example shown here, two values written with the same key contribute to the same direction. Normalization produces a mixture, not a guaranteed latest-value lookup. Similar keys can also interfere. Making the state larger gives it more room; it does not remove the capacity constraint.</p>
<details class="extra"><summary>Kernel similarity, outer products, normalization, and chunked execution</summary><div class="extra-body">
<figure id="c6-vf-01-kernel"><img alt="Change similarity before regrouping" decoding="async" loading="lazy" src="figures/en/attention-evolution-c6-vf-01-kernel.svg"/></figure><p class="figure-caption"><em>Figure 6.4. Factorized kernel similarity enables the regrouping that ordinary softmax does not.</em></p><details><summary>Technical note: Change similarity before regrouping</summary><div class="detail-body"><p>The similarity is changed before regrouping. A nonnegative feature kernel allows the denominator to be accumulated separately through z. Unless a particular approximation is specified and analyzed, this should not be described as an exact replacement for the exponential softmax kernel.</p><div class="equation">Softmax kernel: exp(qᵀk/√dₖ)
Here: κ(q,k)=φ(q)ᵀφ(k) ≥ 0
[Φ(Q)Φ(K)ᵀ]V = Φ(Q)[Φ(K)ᵀV]</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>.</p></div></details>
<p>Softmax attention cannot be regrouped by simply moving parentheses around its nonlinear normalization. The linear form here first uses a factorized nonnegative similarity κ(q,k)=φ(q)ᵀφ(k). That makes it possible to accumulate the key–value products before reading with a query. It is a different attention form, not a free exact rewrite of softmax.</p>
<figure id="c6-vf-02-outer-product"><img alt="An outer product writes an association" decoding="async" loading="lazy" src="figures/en/attention-evolution-c6-vf-02-outer-product.svg"/></figure><p class="figure-caption"><em>Figure 6.5. Adding an outer product writes an association into the same fixed shape rather than appending a token row.</p><div class="equation">φ(kₜ) ∈ ℝᵐ; vₜ ∈ ℝᵈᵛ

<figure id="c6-vf-03-normalization"><img alt="Read S, then normalize using z" decoding="async" loading="lazy" src="figures/en/attention-evolution-c6-vf-03-normalization.svg"/></figure><p class="figure-caption"><em>Figure 6.6. Other recurrent models may use different normalizations.</p><div class="equation">Sₜ = Sₜ₋₁ + φ(kₜ)vₜᵀ
zₜ = zₜ₋₁ + φ(kₜ)
oₜ = Sₜᵀφ(qₜ)/(zₜᵀφ(qₜ))</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>.</p></div></details>
<figure id="c6-vf-04-execution"><img alt="One rule, recurrent or chunkwise" decoding="async" loading="lazy" src="figures/en/attention-evolution-c6-vf-04-execution.svg"/></figure><p class="figure-caption"><em>Figure 6.7. <p>For this normalized kernel form, retain both an association matrix S and a key-feature sum z. Other recurrent architectures use other normalization and gating choices. Fixed persistent decode state also says nothing by itself about total training activation memory.</p>
<pre><code class="language-python">def linear_step(q, k, v, state, normalizer):
    # This feature map keeps m equal to the query/key width.
    qf = torch.nn.functional.elu(q.float()) + 1
    kf = torch.nn.functional.elu(k.float()) + 1
    state = state + kf.unsqueeze(-1) * v.float().unsqueeze(-2)
    normalizer = normalizer + kf
    numerator = torch.einsum('...m,...mv-&gt;...v', qf, state)
    denominator = (qf * normalizer).sum(-1).clamp_min(1e-6)
    return numerator / denominator.unsqueeze(-1), state, normalizer</code></pre>

<p>A finite state needs a policy for what should remain. First, give it a way to forget.</p>
<h2 id="chapter-7">7. RetNet and GLA: Learning What to Forget</h2>
<p>An additive state keeps accumulating writes. Multiplying the old state by a retention factor before adding the new write gives older contributions less influence. In the controlled example, that means an earlier A can fade while a new B is written at full strength.</p>
<figure id="n07-example"><img alt="Decay old writes, then add the new one" decoding="async" loading="lazy" src="figures/en/attention-evolution-n07-example.svg"/></figure><p class="figure-caption"><em>Figure 7.1. Decay reduces old contributions without changing the strength of the new additive write.</em></p><details><summary>Technical note: Decay old writes, then add the new one</summary><div class="detail-body"><p>This controlled example reads raw state outputs before model-specific output normalization. Use the same unit key and query to compare no decay with retention factor ¼. The new value B is still written at full strength. No prediction-error correction is performed.</p><div class="equation">k=q=e₁; old S=e₁Aᵀ
No decay: S′=S+e₁Bᵀ; S′ᵀq=A+B
Decay: S′=¼S+e₁Bᵀ; S′ᵀq=¼A+B</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2307.08621">Retentive Network, §2</a>; <a href="https://arxiv.org/pdf/2312.06635v6">Gated Linear Attention, §4</a>.</p></div></details>
<p><strong>Retentive Network (RetNet)</strong> makes a decayed associative read available in parallel, recurrent, and chunkwise forms. These are different ways to compute the same core rule, with position transforms, normalization, and gates completing the module.</p>
<figure id="n07-retnet"><img alt="One retention rule, three forms" decoding="async" loading="lazy" src="figures/en/attention-evolution-n07-retnet.svg"/></figure><p class="figure-caption"><em>Figure 7.2. The retention core has equivalent parallel, recurrent, and chunkwise forms.</em></p><details><summary>Technical note: One retention rule, three forms</summary><div class="detail-body"><p>A causal decay mask weights older contributions in the parallel form; the recurrent form carries the decayed state. Full RetNet adds positional transformations, multi-scale retention, normalization, and output gating. Those module components should not be confused with the simplified scalar-decay core shown here.</p><div class="equation">Sₜ = γSₜ₋₁ + kₜvₜᵀ; oₜ=Sₜᵀqₜ
O = ((QKᵀ) ⊙ D)V
Dᵢⱼ=γ⁽ⁱ⁻ʲ⁾ for j≤i, and 0 otherwise</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2307.08621">Retentive Network, §2</a>.</p></div></details>
<p><strong>Gated Linear Attention (GLA)</strong> makes retention depend on the input and can control it along key-feature channels. Forgetting is then more selective than one scalar applied to an entire head. The efficient training algorithm must also account for the products of those gates over time.</p>
<details class="extra"><summary>Where a gate acts, and how GLA computes it efficiently</summary><div class="extra-body">

<figure id="n07-gla-chunks"><img alt="GLA brings gates into chunked training" decoding="async" loading="lazy" src="figures/en/attention-evolution-n07-gla-chunks.svg"/></figure><p class="figure-caption"><em>Figure 7.4. <details class="extra"><summary>The related state-space route: Mamba and SSD</summary><div class="extra-body">
<figure id="c7-vf-03-mamba"><img alt="Mamba: select how the state changes" decoding="async" loading="lazy" src="figures/en/attention-evolution-c7-vf-03-mamba.svg"/></figure><p class="figure-caption"><em>Figure 7.5. <p>A <strong>state-space model (SSM)</strong> carries a latent dynamical state. Mamba makes the transition, input, and readout selective through input-dependent parameterization. It belongs in this comparison because it also manages a recurrent state, but its complete module is not simply ordinary softmax attention under another name.</p>
<figure id="n07-ssd"><img alt="SSD depends on matrix structure" decoding="async" loading="lazy" src="figures/en/attention-evolution-n07-ssd.svg"/></figure><p class="figure-caption"><em>Figure 7.6. Combine that mask with content factors to obtain the sequence operator. SSD connects those structured forms to state-space recurrence; an arbitrary lower-triangular or softmax matrix need not have the required structure.</p><div class="equation">Lᵢⱼ = ∏ᵤ₌ⱼ₊₁ⁱ aᵤ for j≤i
Core sequence operator: Y=(L⊙QKᵀ)X</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2405.21060">Transformers Are SSMs, §3–6</a>.</p></div></details>
<p><strong>State Space Duality (SSD)</strong>, developed with Mamba-2, connects particular state-space recurrences to structured attention-like matrix computations. The matrix structure is the reason efficient dual forms exist. It is not a claim that every SSM equals arbitrary softmax attention.</p>
</div></details>
<p>Decay can weaken old content. It still does not ask whether the state’s existing prediction disagrees with the new information.</p>
<h2 id="chapter-8">8. DeltaNet: Correcting Stored Associations</h2>
<p>Suppose a write key already retrieves A, but the incoming target is B. Adding B leaves both contributions in the state. A <strong>delta-rule update</strong> first predicts the current value, subtracts that prediction from B, and writes the resulting error.</p>
<figure id="n08-delta"><img alt="To write B, subtract the predicted A" decoding="async" loading="lazy" src="figures/en/attention-evolution-n08-delta.svg"/></figure><p class="figure-caption"><em>Figure 8.1. A delta write updates the error between the incoming target and the state’s current prediction.</em></p><details><summary>Technical note: To write B, subtract the predicted A</summary><div class="detail-body"><p>Use the write key to predict the value currently associated with that direction, then write a β-scaled residual. The diagram chooses β=¾, giving a partial correction. The following query reads the updated state. These raw state outputs isolate the recurrence, not task-level answer accuracy.</p><div class="equation">v̂ₜ = Sₜ₋₁ᵀkₜ; δₜ = vₜ−v̂ₜ
Sₜ = Sₜ₋₁ + βₜkₜδₜᵀ
oₜ = Sₜᵀqₜ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2102.11174">Linear Transformers Are Secretly Fast Weight Programmers</a>; <a href="https://arxiv.org/pdf/2406.06484">Parallelizing Linear Transformers with the Delta Rule</a>.</p></div></details>
<p>The write key performs this diagnostic read. The ordinary query then reads the updated state. A learned step size β controls how much correction is applied. Complete replacement is a special case under specific normalization and step-size conditions, not a universal guarantee.</p>
<p><strong>Gated DeltaNet (GDN)</strong> combines decay and correction. First decay the old state; then predict from that decayed state and correct its error. The order is part of the mechanism.</p>
<figure id="c8-vf-03-gated-delta"><img alt="GDN: decay first, then correct" decoding="async" loading="lazy" src="figures/en/attention-evolution-c8-vf-03-gated-delta.svg"/></figure><p class="figure-caption"><em>Figure 8.2. Gated DeltaNet predicts from the decayed state before applying a corrective write.</em></p><details><summary>Technical note: GDN: decay first, then correct</summary><div class="detail-body"><p>Decay and correction are complementary operations. Compute the prediction from S̄, then add the residual update to that same S̄. Multiplying the final new-write term by α again would implement a different recurrence. The paper’s state orientation is transposed here to keep key×value notation consistent.</p><div class="equation">S̄ₜ = αₜSₜ₋₁
δₜ = vₜ−S̄ₜᵀkₜ
Sₜ = S̄ₜ + βₜkₜδₜᵀ
= αₜ(I−βₜkₜkₜᵀ)Sₜ₋₁ + βₜkₜvₜᵀ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2412.06464v3">Gated Delta Networks, §3.1</a>.</p></div></details>
<details class="extra"><summary>Additive writes versus delta writes, step by step</summary><div class="extra-body">
<figure id="c8-vf-02-delta-compare"><img alt="Write again: accumulate or correct?" decoding="async" loading="lazy" src="figures/en/attention-evolution-c8-vf-02-delta-compare.svg"/></figure><p class="figure-caption"><em>Figure 8.3. With a unit key and β=1, the idealized delta update replaces that direction’s prediction.</em></p><details><summary>Technical note: Write again: accumulate or correct?</summary><div class="detail-body"><p>The unit-key condition matters: the correction seen when reading back with k is scaled by kᵀk. A smaller β gives a partial correction. Other correlated keys can be affected, so this calculation is not a universal latest-write guarantee for all stored associations.</p><div class="equation">Sₜᵀk = Sₜ₋₁ᵀk + β(v−Sₜ₋₁ᵀk)(kᵀk)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2102.11174">Linear Transformers Are Secretly Fast Weight Programmers</a>; <a href="https://arxiv.org/pdf/2406.06484">Parallelizing Linear Transformers with the Delta Rule</a>.</p></div></details>
<figure id="c8-vf-01-delta-flow"><img alt="Delta: read, compare, then correct" decoding="async" loading="lazy" src="figures/en/attention-evolution-c8-vf-01-delta-flow.svg"/></figure><p class="figure-caption"><em>Figure 8.4. Prediction uses the write key; the subsequent read uses the query.</em></p><details><summary>Technical note: Delta: read, compare, then correct</summary><div class="detail-body"><p>The key and query participate in different operations even when a toy example sets their directions equal. First reconstruct the current association at k, compare it with the incoming value, and edit the matrix. Then read the new matrix at q. This is the core delta-rule information flow.</p><div class="equation">v̂ₜ=Sₜ₋₁ᵀkₜ
δₜ=vₜ−v̂ₜ
Sₜ=Sₜ₋₁+βₜkₜδₜᵀ
oₜ=Sₜᵀqₜ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2102.11174">Linear Transformers Are Secretly Fast Weight Programmers</a>; <a href="https://arxiv.org/pdf/2406.06484">Parallelizing Linear Transformers with the Delta Rule</a>; <a href="https://arxiv.org/pdf/2412.06464v3">Gated Delta Networks, §3.1</a>.</p></div></details>
<p>The delta rule can be understood as an online update that reduces reconstruction error for the current key–value association. Nonorthogonal keys can still affect one another. Efficient chunkwise algorithms also matter: a useful recurrence needs a practical training path, not just a compact decode equation.</p>
</div></details>
<p>GDN’s scalar decay still weakens every direction in a head together. The next refinement is to make that forgetting more granular.</p>
<h2 id="chapter-9">9. KDA: Forgetting One Feature at a Time</h2>
<p><strong>Kimi Delta Attention (KDA)</strong> replaces GDN’s headwise scalar decay with a vector of retention factors along the key-feature axis. It keeps delta-rule correction, but lets different directions retain different amounts of their old content.</p>
<figure id="n09-kda"><img alt="Why forget every direction equally?" decoding="async" loading="lazy" src="figures/en/attention-evolution-n09-kda.svg"/></figure><p class="figure-caption"><em>Figure 9.1. KDA can retain one key-feature direction more strongly while editing another.</em></p><details><summary>Technical note: Why forget every direction equally?</summary><div class="detail-body"><p>Both sides of the toy comparison start from the same two-direction state and correct direction 1 toward B. They use the same β=¾. Scalar retention weakens direction 2 by ¼; the chosen channelwise retention keeps ¾ of it. The comparison isolates gate granularity rather than claiming semantic field-level control.</p><div class="equation">Dₜ=Diag(αₜ); S̄ₜ=DₜSₜ₋₁
δₜ=vₜ−S̄ₜᵀkₜ
Sₜ=S̄ₜ+βₜkₜδₜᵀ; oₜ=Sₜᵀqₜ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2510.26692">Kimi Linear, §3</a>; <a href="https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/kda.py">KDA layer implementation</a>.</p></div></details>
<p>Our two-direction example holds the write key, target, and correction strength fixed. Both paths update direction 1, but the channelwise gate can preserve more of direction 2. This isolates what changed: <strong>the granularity of forgetting, not a new guarantee of perfect recall.</strong></p>
<figure id="n09-family"><img alt="Forgetting and correction are separate" decoding="async" loading="lazy" src="figures/en/attention-evolution-n09-family.svg"/></figure><p class="figure-caption"><em>Figure 9.2. Forgetting granularity and delta correction are independent design axes.</em></p><details><summary>Technical note: Forgetting and correction are separate</summary><div class="detail-body"><p>Compare state cores rather than entire model blocks. A method may use additive or corrective writes, and uniform or feature-dependent retention. KDA combines channelwise forgetting with a delta-rule edit. Additional module operations, training algorithms, and normalization can still differ.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2307.08621">Retentive Network, §2</a>; <a href="https://arxiv.org/pdf/2312.06635v6">Gated Linear Attention, §4</a>; <a href="https://arxiv.org/pdf/2412.06464v3">Gated Delta Networks, §3.1</a>; <a href="https://arxiv.org/pdf/2510.26692">Kimi Linear, §3</a>; <a href="https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/kda.py">KDA layer implementation</a>.</p></div></details>
<p>Forgetting and correction are separate design choices. Additive linear attention, gated accumulation, delta updates, and channelwise gated delta updates occupy different positions on these axes. The full model also includes projections, normalization, short convolutions, and output gating.</p>
<details class="extra"><summary>Rowwise decay, update order, and the complete KDA state</summary><div class="extra-body">
<figure id="c9-vf-01-row-decay"><img alt="KDA replaces one decay with a vector" decoding="async" loading="lazy" src="figures/en/attention-evolution-c9-vf-01-row-decay.svg"/></figure><p class="figure-caption"><em>Figure 9.3. A diagonal retention matrix scales the key-feature rows independently.</em></p><details><summary>Technical note: KDA replaces one decay with a vector</summary><div class="detail-body"><p>In the key×value orientation used throughout this article, D acts on the left of S. The value axis is not the axis controlled by this retention gate. KDA subsequently applies a delta correction based on the decayed state.</p><div class="equation">Dₜ=Diag(αₜ) ∈ ℝᵈᵏˣᵈᵏ
Sₜ=(I−βₜkₜkₜᵀ)DₜSₜ₋₁+βₜkₜvₜᵀ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2510.26692">Kimi Linear, §3</a>; <a href="https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/kda.py">KDA layer implementation</a>.</p></div></details>
<figure id="c9-vf-02-update-order"><img alt="Decay channels before predicting" decoding="async" loading="lazy" src="figures/en/attention-evolution-c9-vf-02-update-order.svg"/></figure><p class="figure-caption"><em>Figure 9.4. Decay, predict, and correct in that order.</em></p><details><summary>Technical note: Decay channels before predicting</summary><div class="detail-body"><p>Both the residual’s prediction and the base of the final update must use the same decayed matrix. The KDA equation and author implementations make this ordering explicit. Computing the residual from the undecayed old matrix changes the result even if the final update includes a decay factor.</p><div class="equation">S̄ₜ=DₜSₜ₋₁
v̂ₜ=S̄ₜᵀkₜ
Sₜ=S̄ₜ+βₜkₜ(vₜ−v̂ₜ)ᵀ</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2510.26692">Kimi Linear, §3</a>; <a href="https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/kda.py">KDA layer implementation</a>.</p></div></details>
<figure id="c9-vf-03-module-state"><img alt="A full KDA layer has more state" decoding="async" loading="lazy" src="figures/en/attention-evolution-c9-vf-03-module-state.svg"/></figure><p class="figure-caption"><em>Figure 9.5. Persistent state accounting must include the short convolution, not only the association matrix.</em></p><details><summary>Technical note: A full KDA layer has more state</summary><div class="detail-body"><p>A complete KDA layer can include Q/K/V projections, short convolutions, activations, normalization, gates, and an output projection. The figure highlights the separately retained convolution state. Fixed shape of the recurrent core is therefore not the entire module’s state-size formula.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2510.26692">Kimi Linear, §3</a>; <a href="https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/kda.py">KDA layer implementation</a>.</p></div></details>
<pre><code class="language-python">def kda_step(q, k, v, state, alpha, beta):
    # Inputs have already been projected and Q/K normalized.
    # state: [..., dk, dv]; alpha: [..., dk]; beta: [...]
    decayed = state.float() * alpha.float().unsqueeze(-1)
    prediction = torch.einsum('...k,...kv-&gt;...v', k.float(), decayed)
    residual = v.float() - prediction
    edit = k.float().unsqueeze(-1) * residual.unsqueeze(-2)
    updated = decayed + beta.float()[..., None, None] * edit
    out = torch.einsum('...k,...kv-&gt;...v', q.float(), updated)
    return out, updated</code></pre>
<p>This is the state core only. A complete module must also retain any short-convolution state. The toy readout omits the query scaling and post-read processing used by a particular implementation.</p>
</div></details>
<p>Selective forgetting makes finite memory more useful. It does not make retained historical entries redundant.</p>
<h2 id="chapter-10">10. Hybrid Attention: Combining Different Memories</h2>
<p>Recurrent layers offer a fixed-shape state. Historical attention offers a direct content-dependent read over retained positions. A <strong>hybrid</strong> puts these interfaces together so different layers or branches can perform different kinds of sequence mixing.</p>
<figure id="n10-hybrid"><img alt="Read old memory; carry new memory forward" decoding="async" loading="lazy" src="figures/en/attention-evolution-n10-hybrid.svg"/></figure><p class="figure-caption"><em>Figure 10.1. Representations move through depth while each layer updates its own memory across time.</em></p><details><summary>Technical note: Read old memory; carry new memory forward</summary><div class="detail-body"><p>The Kimi K3 configuration repeats three KDA layers followed by one Gated MLA, plus an additional final Gated MLA. The report uses NoPE for MLA. The diagram omits feed-forward and other block operations. Its finite KDA states do not remove the MLA layers’ growing per-position caches.</p><div class="equation">Persistent model state = Σ recurrent-layer states + Σ historical-layer caches + auxiliary retained state</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2607.24653v1">Kimi K3, §2.1–2.2</a>.</p></div></details>
<p>The Kimi K3 report describes repeated groups of three KDA layers followed by one Gated MLA layer, with an additional Gated MLA layer at the end. Representations flow vertically through the model; each layer maintains its own memory across token steps. The fixed KDA states and growing MLA caches coexist.</p>
<p>Kimi K3 applies NoPE to its MLA queries and keys. Its KDA layers supply position-sensitive, recency-aware mixing between global attention layers. This is why the DeepSeek-V2 positional-key layout from Chapter 4 should not be pasted indiscriminately onto every architecture called MLA.</p>
<details class="extra"><summary>What a model-level memory budget must include</summary><div class="extra-body">
<p>A hybrid’s persistent memory is the sum of its recurrent states, historical attention caches, and other retained module state. A 3:1 layer pattern is one model’s configuration, not a universal hybrid recipe or a measured speedup. Dimensions, precision, batching, training, and kernels still matter.</p>
<p>The roles can complement one another: a recurrent state need not reproduce every token for a historical layer to retain a route to details. Whether a particular division works well must be established by training and task evaluation.</p>
</div></details>
<details class="extra"><summary>An output gate is different from a forget gate</summary><div class="extra-body">
<figure id="n10-outputgate"><img alt="An output gate follows the read" decoding="async" loading="lazy" src="figures/en/attention-evolution-n10-outputgate.svg"/></figure><p class="figure-caption"><em>Figure 10.2. An output gate scales the attention readout before the output projection.</em></p><details><summary>Technical note: An output gate follows the read</summary><div class="detail-body"><p>At the illustrated G1 placement, the gate modulates channels after attention has computed its read. It is different from a retention gate acting on the old recurrent matrix. Gate rank, parameterization, and placement are model-specific; do not infer them from the word “gated” alone.</p><div class="equation">h = SDPA(Q,K,V)
g = sigmoid(W_g x)
o = W_O(h⊙g)</div><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2505.06708">Gated Attention for Large Language Models</a>; <a href="https://arxiv.org/pdf/2607.24653v1">Kimi K3, §2.1–2.2</a>.</p></div></details>
<p>A channelwise output gate can modulate the attention readout before the output projection. It regulates the information forwarded from the read. A state-retention gate instead changes what remains in recurrent memory. Both may be called “gating,” but they act on different objects.</p>
</div></details>
<p>So far we have changed memory representations and read/write rules. We can also keep a rule and execute it more efficiently.</p>

<p><strong>Ring Attention</strong> distributes sequence blocks and circulates KV while queries stay local. Overlapping communication with block computation can make long-context execution practical across devices. <p>These techniques can compose with architectural choices. To understand a model, identify both the operation it specifies and the system that executes it.</p>
<h2 id="chapter-12">12. How to Read a New Architecture</h2>
<p>Return to the reports that opened this article. Instead of collecting acronyms, ask four questions: <strong>What is stored? What is read? What is updated? Which costs still grow?</strong></p>
<p>DeepSeek-V4.1-Flash’s CSA2 makes cross-layer reuse explicit. A Full layer produces global KV and an index selection. A Reindex layer reuses global KV but scores it again with its own indexer query. A Reuse layer retains both the shared KV and an existing selection. Every mode still has its own main query and local-window KV.</p>
<figure id="c12-vf-02-csa2"><img alt="CSA2: reuse KV, or reuse the selection" decoding="async" loading="lazy" src="figures/en/attention-evolution-c12-vf-02-csa2.svg"/></figure><p class="figure-caption"><em>Figure 12.1. CSA2 separates reusing global KV from reusing the indices that select it.</em></p><details><summary>Technical note: CSA2: reuse KV, or reuse the selection</summary><div class="detail-body"><p>Full mode generates global main KV and indexer K and selects indices. Reindex reuses shared KV and indexer K but rescoring uses its own indexer query. Reuse also keeps a valid preceding selection for the same global KV. Every layer retains its own main query and local-window KV. The diagram does not imply that local caches disappear.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2609.19969">DeepSeek-V4.1-Flash, §2.2–2.3</a>.</p></div></details>
<p>Cache sharing and selection sharing save different work. They should be counted separately. The report’s causal encoder–decoder structure supplies the source representation for global KV; it is not itself a statement that every decoder layer uses identical projected KV.</p>

These structural descriptions do not produce a controlled speed ranking: full-model configuration, training, kernels, and workload remain different.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2609.19969">DeepSeek-V4.1-Flash, §2.2–2.3</a>; <a href="https://arxiv.org/pdf/2607.24653v1">Kimi K3, §2.1–2.2</a>.</p></div></details>

<h2 id="chapter-13">13. What Attention’s Evolution Adds Up To</h2>
<p>The history becomes easier to follow once we stop treating it as a succession of better attention formulas. Its recurring problem is <strong>how to make past information useful without making every future step increasingly expensive.</strong></p>
<figure id="n13-memory-system"><img alt="From reading context to managing memory" decoding="async" loading="lazy" src="figures/en/attention-evolution-n13-memory-system.svg"/></figure><p class="figure-caption"><em>Figure 13.1. Attention’s scope expands from a read operator to the organization of a memory system.</em></p><details><summary>Technical note: From reading context to managing memory</summary><div class="detail-body"><p>This is a synthesis of the preceding mechanisms, not a claim that each newer method replaces the earlier ones. Retained entries, associative states, update policies, composition, and physical execution answer different parts of the same question: how can useful past information influence the next computation at an affordable cost?</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/1706.03762">Attention Is All You Need, §3.2</a>; <a href="https://arxiv.org/pdf/2006.16236">Transformers Are RNNs, §3</a>; <a href="https://arxiv.org/html/2501.00663v1#S3">Titans</a>; <a href="https://arxiv.org/html/2404.07143v1#S2">Infini-attention</a>; <a href="https://arxiv.org/html/2203.08913v1#S3.SS1">Memorizing Transformers</a>.</p></div></details>
<p>First came a more flexible read. Then came smaller or shared entries, fewer reads, finite states, selective forgetting, corrective writes, and combinations of those interfaces. Execution techniques made these operations fit real memory hierarchies. Each step moved a different part of the cost–capability boundary.</p>

<p>The broader lesson is a change of scope: <strong>attention design increasingly includes the organization of memory, not just the score used for a read.</strong> That does not make every cache a human-like memory. It gives us a more useful set of questions about capability, retention, and cost.</p>
<h2 id="chapter-14">14. Where Memory Systems Could Go Next</h2>
<p>The following is an outlook, not a report of a settled architecture. Existing work already combines local detail, compressed or retrieved history, and recurrent state. The open question is how well the model can learn to divide work among them.</p>
<figure id="n14-memory-tiers"><img alt="A possible division of memory roles" decoding="async" loading="lazy" src="figures/en/attention-evolution-n14-memory-tiers.svg"/></figure><p class="figure-caption"><em>Figure 14.1. Different memory interfaces could specialize in recent detail, compact history, and updated associations.</em></p><details><summary>Technical note: A possible division of memory roles</summary><div class="detail-body"><p>Dashed connections denote a candidate organization to test, not an implemented architecture or a proven routing policy. Existing retrieval and recurrent-memory research motivates the roles, but does not establish universal proportions. A finite state cannot be assumed to reconstruct discarded detail; training and task results must justify the division.</p><p class="reference-note">Primary references: <a href="https://arxiv.org/pdf/2607.24653v1">Kimi K3, §2.1–2.2</a>; <a href="https://arxiv.org/html/2501.00663v1#S3">Titans</a>; <a href="https://arxiv.org/html/2404.07143v1#S2">Infini-attention</a>; <a href="https://arxiv.org/html/2203.08913v1#S3.SS1">Memorizing Transformers</a>.</p></div></details>
<p>Recent detail might remain directly accessible; older information might be compressed or selectively retrieved; a recurrent state might track associations that need continual updating. A controller could learn what to write and which source to consult. These roles need not occupy one literal three-tier module, and a state cannot be assumed to reconstruct details it no longer retains.</p>
<p>That leads to a stronger set of design questions: <strong>What should persist? What should be revised? When should a cheap state read be supplemented by an explicit retrieval?</strong> Architectures such as <a href="https://arxiv.org/html/2404.07143v1#S2">Infini-attention</a>, <a href="https://arxiv.org/html/2203.08913v1#S3.SS1">Memorizing Transformers</a>, and <a href="https://arxiv.org/html/2501.00663v1#S3">Titans</a> explore parts of this space. They do not establish one universally best division of memory roles.</p>
<figure id="n14-memory-lifecycle"><img alt="Memory also needs a lifecycle" decoding="async" loading="lazy" src="figures/en/attention-evolution-n14-memory-lifecycle.svg"/></figure><p class="figure-caption"><em>Figure 14.2. A useful memory system also needs policies for reuse, movement, and release.</em></p><details><summary>Technical note: Memory also needs a lifecycle</summary><div class="detail-body"><p>The repeated colors show physical relocation of the same KV content across storage tiers. LMCache documents real reuse and movement mechanisms. The further semantic policy—what an assistant should remember, revise, or forget across sessions—is a separate open design problem. No performance or capacity ratio is implied by the boxes.</p><p class="reference-note">Primary references: <a href="https://docs.lmcache.ai/">LMCache documentation</a>; <a href="https://arxiv.org/html/2501.00663v1#S3">Titans</a>; <a href="https://arxiv.org/html/2404.07143v1#S2">Infini-attention</a>; <a href="https://arxiv.org/html/2203.08913v1#S3.SS1">Memorizing Transformers</a>.</p></div></details>
<p>The serving system has related decisions to make. KV content may reside on a GPU, in CPU memory, or in storage; it can be reused, moved, or released. Systems such as <a href="https://docs.lmcache.ai/">LMCache</a> already implement cache reuse and movement. Keeping a cache longer is a physical capability. Understanding and integrating a user’s experiences across sessions is a different semantic capability.</p>
<details class="extra"><summary>Which predictions would be worth testing?</summary><div class="extra-body">
<p>We would look for evidence that a learned memory policy improves the joint quality–cost tradeoff: retaining information that matters, revising stale associations, retrieving details when a compressed state is insufficient, and doing so within a measured storage and latency budget. Comparisons should include workloads that expose forgetting, interference, revision, and long-range detail retrieval.</p>
<p>Cross-layer sharing and physical cache tiers offer additional opportunities, but their benefits depend on reuse patterns and implementation. A model’s semantic decisions and a serving system’s placement decisions must agree on what information exists, what is reusable, and when it is safe to discard it.</p>
<p>These are hypotheses to validate through training and tasks. A plausible block diagram, a lower asymptotic term, or a cache that survives a restart is not enough evidence by itself.</p>
</div></details>
<p>Attention began by giving a decoder a better way to look back. Its evolution now asks how a model should organize the past: <strong>what to keep, how to access it, and how to change it when the world moves on.</strong> Follow those choices, and the next unfamiliar attention name becomes a design we can inspect.</p>
